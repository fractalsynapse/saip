The training gateway listens on the port configured in `training.port` (default `8001`). All endpoints accept and return JSON.

Base URL: `http://<host>:<training.port>`

The training gateway exposes a single API surface:

- **Learning API** (`/v1/learning/*`) — training strategy registration, job management, feedback, and optimization

Data ingestion is handled by the inference gateway (see [Inference API](/saip/reference/api-inference/)). Processed data flows between the two services via R2 object storage.

## Running the Gateway

The training gateway is a program that listens. `node training/dist/index.js` (the container `CMD`)
binds the port from `saip.yaml`'s `training.port`, overridable by `SAIP_TRAINING_PORT`, and serves the
routes on this page:

```bash
SAIP_TRAINING_PORT=8001 node training/dist/index.js
# [saip-training] storage: R2StorageProvider
# [saip-training] Learning API listening on :8001

curl -s http://127.0.0.1:8001/health
curl -s -H "Authorization: Bearer $SAIP_TOKEN" http://127.0.0.1:8001/v1/learning/strategies
```

:::warning[It did not always listen]
Until #218 the entry point logged `Gateway starting...` and exited 0 without binding a socket, while
compose mapped port 8001 and the docs showed `curl http://localhost:8001/...`. Every route on this
page was reachable only from inside the test process. `training/tests/serve-program.test.ts` now
starts the built artifact and fails if nothing answers.
:::

### Who runs a job

Queuing a job writes a record; nothing executes it unless a process claims it. Claiming is opt-in:

```bash
SAIP_TRAINING_RUN=1 node training/dist/index.js    # serve AND claim queued jobs
```

Without it the gateway serves reads and accepts jobs but never touches the GPU. That is deliberate.
On a single card, training and serving are time-shared through `saip awake` / `saip sleep` — a gateway
that claimed jobs the moment it booted would seize memory the inference engine is holding, and the
symptom would be an OOM in whichever process lost. The operator sets `SAIP_TRAINING_RUN=1` in the
window where the card belongs to training.

| Variable | Default | Meaning |
|---|---|---|
| `SAIP_TRAINING_PORT` | `training.port` from `saip.yaml` (8001) | Listen port |
| `SAIP_TRAINING_RUN` | unset | When `1`, poll for `queued` jobs and execute them one at a time |
| `SAIP_TRAINING_POLL_SECONDS` | `5` | Interval between claims while running |
| `SAIP_TRAINING_DATA_DIR` | — | Host directory mirrored to the worker's `/app/data`; unset means no mirror |
| `SAIP_ADAPTER_OUTPUT_DIR` | — | Host directory for `/app/output`; unset means no artifact is found |

## Authentication

`/v1/learning/jobs*` is authenticated as a **prefix**. Hono's `app.use('/v1/learning/jobs', mw)`
matches that exact path and not its subpaths, so adding `GET /v1/learning/jobs/:id` under the old
pattern would publish every persisted job — adapter, dataset hash, parameters — to anonymous
readers. The middleware mounts on `/v1/learning/jobs/*`.

## Authentication

Job-mutating routes (`POST /v1/learning/jobs`) are protected by the same pluggable
[AuthProvider](/saip/reference/security-model/) as the inference gateway: send `Authorization: Bearer <token>`, and the authenticated caller's default training adapter is used unless the request names one explicitly. **Fail-closed** — without a valid bearer token (and with `security.dev_mode` false), requests receive `401`. Read-only routes such as `GET /v1/learning/strategies` may remain open depending on deployment policy.

## Architecture Overview

The SAIP platform separates concerns across two gateways with **R2 as the handoff boundary**:

```
┌─────────────────────────────┐          ┌─────────────────────────────┐
│    Inference Gateway        │          │     Training Gateway        │
│                             │          │                             │
│  Data API (/v1/data/*)      │          │  Learning API (/v1/learning)│
│  Document Processors        │          │  Training Strategy Plugins  │
│  ├─ markdown-processor      │          │  ├─ knowledge_embedding     │
│  ├─ code-processor          │          │  ├─ corrective_sft          │
│  ├─ pdf-processor (Marker)  │          │  ├─ weighted_kto            │
│  └─ jsonl-processor         │          │  └─ (future strategies...) │
│                             │          │                             │
│  Writes processed data ──────────► R2 ◄──── Reads processed data    │
│                             │          │                             │
│  Serves model inference     │          │  Runs Axolotl training jobs │
└─────────────────────────────┘          └─────────────────────────────┘
```

### Why This Separation

Document processing often requires model inference — OCR via Marker for PDFs, code analysis, structured extraction. Running these processors on the training GPU would compete with training workloads. By placing the Data API and document processors in the inference gateway:

- The **inference GPU** handles both model serving and document processing during awake mode
- The **training GPU** is 100% dedicated to Axolotl fine-tuning jobs
- R2 serves as a clean handoff boundary: inference writes processed data, training reads it

### Training Strategy Plugins

Each **training strategy plugin** declares which intermediate output formats it can consume from R2. When a learning job references a strategy, the registry loads matching processed data and produces Axolotl datasets in the required format.

Adding a new training method requires only one new strategy plugin — zero changes to data processors or the inference gateway. Multiple strategies can consume the same processed output simultaneously.

The training gateway orchestrates the flow:

```
R2 (processed data) ──→ Training Strategy Plugins
                         ├── knowledge_embedding → completion datasets
                         ├── corrective_sft      → feedback-weighted SFT datasets
                         ├── weighted_kto        → KTO datasets with magnitude weights
                         └── ...extensible
                                ↓
                          Axolotl Runner
                                ↓
                           QLoRA Adapter
                                ↓
                  Upload to R2 + update index
```

# Learning API

## GET /v1/learning/strategies

List registered training strategy plugins.

### Response `200 OK`

```json
{
  "strategies": [
    {
      "name": "knowledge_embedding",
      "description": "Continued pretraining on completion-format datasets",
      "accepted_source_types": ["document", "repository", "dataset"],
      "configurable_params": ["epochs", "learning_rate", "sequence_len"]
    },
    {
      "name": "corrective_sft",
      "description": "Supervised fine-tuning with per-turn feedback weighting",
      "accepted_source_types": ["session", "feedback"],
      "configurable_params": ["epochs", "learning_rate", "turn_weighting"]
    },
    {
      "name": "weighted_kto",
      "description": "Preference learning with scalar reward magnitudes",
      "accepted_source_types": ["feedback"],
      "configurable_params": ["reward_range", "magnitude_weights"]
    }
  ]
}
```

## POST /v1/learning/jobs

Trigger a new training job. Jobs target a **leaf adapter** in the registry; when `strategy` and data selection are omitted, they are inherited from the adapter's declared [training linkage](/saip/reference/adapter-definitions/#training-linkage-training).

### Request Body

| Field           | Type     | Required | Description                                          |
|-----------------|----------|----------|------------------------------------------------------|
| `adapter`       | `string` | No       | Target adapter name from the registry. Defaults to the caller's `users[].adapters.training`. Must be a leaf — composites return `422`. |
| `strategy`      | `string` | No       | Registered training strategy plugin. Defaults to the adapter's declared `training.strategy`. |
| `data_ids`      | `string[]` | No     | Explicit document/session/feedback IDs, ANDed with the adapter's declared `data_scopes`. Matching nothing is `422 empty_scope`, not an empty dataset. |
| `params`        | `object` | No       | Strategy-specific parameter overrides (defaults merge from the adapter's `training.params`). |

:::note[Adapter → Strategy → Data Path]
The registry is what makes this chain explicit: `user → users[].adapters.training → adapter definition → training.strategy + training.data_scopes → matching strategy plugin → dataset`. A job that names only an adapter inherits everything else; explicit fields override per-job for experimentation.
:::

### Response `202 Accepted`

Returns the persisted [job record](#the-job-record). The record is written to
`jobs/<id>.json` **before** the `learning/job-queued` event is emitted: the event is a
notification, the object in storage is the truth.

```json
{
  "id": "train-20261125-lx3k9q-4f2a",
  "caller": "adrian",
  "adapter": "northstar-project",
  "strategy": "corrective_sft",
  "data_scopes": ["sessions", "feedback"],
  "params": {},
  "inherited": { "strategy": true, "data_scopes": true },
  "status": "queued",
  "history": [{ "at": "2026-11-25T12:00:00Z", "status": "queued" }],
  "created_at": "2026-11-25T12:00:00Z",
  "updated_at": "2026-11-25T12:00:00Z"
}
```

### Errors

| Status | Code | Condition |
|--------|------|-----------|
| `401` | `unauthorized` | No bearer token on any `/v1/learning/jobs*` route when `security.dev_mode` is false |
| `404` | `adapter_not_found` | Adapter not in the registry |
| `422` | `composite_not_trainable` | `adapter` names a composite (`trainable: false`) |
| `422` | `unknown_strategy` | `strategy` is not a registered plugin |
| `422` | `forbidden_param` | A `params` key matches `token`/`secret`/`key`/`passw` — see the redaction rule below |
| `422` | `unknown_scope` | An inherited `data_scopes` entry is not `sessions`, `feedback`, `documents` or `library:<name>` |
| `422` | `library_not_found` | `library:<name>` has no materialized manifest at `libraries/<name>/manifest.json` |
| `422` | `empty_scope` | A scope resolved to zero records (no sessions, no feedback, an empty library, or `data_ids` that match nothing) |

:::note[A refusal is still a record]
Queueing resolves the adapter's `data_scopes` against storage **before** accepting the job, so a typo
in a scope name or an empty corpus is a `422` at the boundary instead of a training run that reports
success after un-learning behavior. The refusal is still written to `jobs/<id>.json` with
`status: 'failed'` and the structured error, and it appears in the list routes: an operator asking
"why is there no job for that attempt" gets an answer. Nothing is emitted on
`learning/job-queued` for a refused job, and no configuration is materialized.
:::

:::note[`params` are rejected, not redacted]
A job record is written to cloud storage, and a wizard-passed credential that arrives as a
"training parameter" would otherwise be published to the bucket with the dataset. Rejecting at
the API (`422 forbidden_param`) is the same stance `saip deploy` takes: the value never enters
SAIP state, so there is nothing to sanitize later.
:::

## Job Failure Codes

`error.code` on a record is stable and machine-readable; the runner writes it, never a free-text
message alone.

| Code | Stage | Meaning |
|------|-------|---------|
| `interrupted` | boot | The record said `running` when the gateway started. It is not resumed; re-run as a new job. |
| `empty_scope` | P1 | A declared scope resolved to zero records. Refused at the API before the job is queued. |
| `unknown_scope` | P1 | A `data_scopes` entry is not one of the known scope names. |
| `library_not_found` | P1 | `library:<name>` has no materialized manifest. |
| `no_dataset_rows` | P3 | Rows resolved but nothing carried feedback. |
| `no_base_model` | P4 | The target leaf adapter declares no `base` checkpoint. |
| `config_failed` | P4 | The Axolotl config could not be materialized. |
| `worker_unavailable` | P5 | The `axolotl-worker` container is not reachable from this process. |
| `training_failed` | P5 | Non-zero exit; the captured tail lands in `history[].detail`. |
| `no_artifact` | P6 | The worker exited 0 but wrote no `adapter_config.json` + `adapter_model.safetensors`. |
| `promotion_failed` | P7 | Upload or read-back verification failed; the previous `latest` stays valid. |

Every transition appends to `history`, so a job that failed twice for different reasons shows both
attempts rather than only the last.

## Scope Resolution

`data_scopes` is inherited from the adapter definition (the request offers no override, which is why
`inherited.data_scopes` is `true` by construction). At queue time the training gateway resolves each
entry through the shared `StorageProvider` seam — never a concrete client — so the same code path runs
against memory in tests, the in-process fake in CI, and R2 in production:

| Scope | Resolves to |
|---|---|
| `sessions` | every `sessions/<id>/conversation.jsonl` |
| `feedback` | every `feedback/<id>.json` |
| `documents` | one object per knowledge document, preferring `processed.md`, then `source.<ext>`, then the legacy `content.<ext>` |
| `library:<name>` | the member keys recorded in `libraries/<name>/manifest.json`, verified present |

Libraries are declared in [`libraries:` config](/saip/reference/configuration/#libraries) and
materialized by the inference gateway, which owns the knowledge index; the manifest records the filter
that produced it ([bucket layout](/saip/reference/r2-bucket-layout/#librariesnamemanifestjson)).

The first unresolvable scope aborts the request. A partially-resolved dataset is not a thing: silently
dropping one scope would train on a corpus the operator never chose.

## The Job Record

Every job is one object at `jobs/<id>.json`, plus a `jobs/_index.json` map — the layout documents,
sessions and feedback already use. No database is introduced: the job store is a `StorageProvider`
consumer, so the durability rules and the contract suite in
[Storage selection](/saip/reference/configuration/#storage-selection) apply to it for free. Only
the training gateway writes here.

| Field | Type | Notes |
|-------|------|-------|
| `id` | `string` | `train-<YYYYMMDD>-<base36-ms>-<base36-rand4>`. Unique across restarts — the previous counter reset on boot and minted duplicates. |
| `caller` | `string?` | Authenticated principal, from the existing bearer path |
| `adapter`, `strategy`, `data_scopes`, `data_ids`, `params` | — | Copied verbatim from the resolved job, which is also what the API already returned; persistence does not invent a second shape |
| `inherited` | `{ strategy: boolean, data_scopes: boolean }` | Whether each came from the adapter declaration or the request |
| `status` | `'queued' \| 'running' \| 'succeeded' \| 'failed'` | There is no `completed` state; the runner produces `succeeded` |
| `error` | `{ code, message }?` | Structured, e.g. `interrupted`, `no_artifact` |
| `dataset` | `{ key, sha256, records, format }?` | The `sha256` is the determinism proof for the export |
| `config` | `{ key, sha256 }?` | Materialized `axolotl.yaml` |
| `artifact` | `{ prefix, base_model }?` | Worker output directory |
| `version` | `number?` | Assigned **only** at promotion; links back through the adapter index |
| `history` | `Array<{ at, status, detail? }>` | Append-only transitions, written with every status change |
| `created_at`, `updated_at` | `string` (ISO 8601) | |

### Lifecycle rules

- **Write-ahead.** `queued` is persisted before `learning/job-queued` fires. A consumer that acts
  on the event can always read the record it describes.
- **Single-flight.** One `running` job at a time — one GPU. `queued` jobs are claimed oldest
  `created_at` first.
- **Interrupted, not resurrected.** At boot, every `running` record becomes
  `failed { code: "interrupted" }`. The runner does not resume unknown worker state; a re-run is a
  new job. This is what makes killing a cloud instance survivable: the record says what happened
  instead of lying about a process that no longer exists.
- **Transitions append to `history`** and rewrite the object (bytes → index ordering, as above).

### Example

```bash
# Minimal: inherit strategy + data scopes from the adapter's registry entry
curl -X POST http://localhost:8001/v1/learning/jobs \
  -H "Content-Type: application/json" \
  -d '{ "adapter": "northstar-project" }'

# Explicit: override strategy params for one experiment
curl -X POST http://localhost:8001/v1/learning/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "adapter": "coding",
    "strategy": "knowledge_embedding",
    "data_ids": ["doc-20250115-001"],
    "params": { "epochs": 3, "learning_rate": 2e-5 }
  }'
```

## GET /v1/learning/jobs

List job records. The response mirrors the Data API's document list, so a client that pages one
pages both.

### Query Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `adapter` | `string` | Filter by target adapter name. |
| `status` | `string` | Filter by status (`queued`, `running`, `succeeded`, `failed`). |
| `limit` | `number` | Maximum records to return. Default `50`. |
| `offset` | `number` | Pagination offset. Default `0`. |

### Response `200 OK`

```json
{
  "entries": [
    { "id": "train-20261125-lx3k9q-4f2a", "adapter": "coding", "strategy": "corrective_sft", "status": "queued", "created_at": "2026-11-25T12:00:00Z" }
  ],
  "total": 1,
  "limit": 50,
  "offset": 0
}
```

## GET /v1/learning/jobs/:id

Fetch one [job record](#the-job-record) by id. This is the route that makes a job queryable after
the process that queued it is gone, which is the entire point of persisting it.

### Response `200 OK`

The full record.

### Errors

| Status | Code | Condition |
|--------|------|-----------|
| `401` | `unauthorized` | Missing bearer token (non-`dev_mode`) |
| `404` | `job_not_found` | No record at that id |

## POST /v1/learning/feedback

> **Not implemented here.** Feedback is written through the inference Data API (`POST /v1/data/feedback`); whether this route should also exist on the training gateway is open in #208.

Submit a feedback record linked to a session. Used as reward signal for weighted KTO and corrective SFT training strategies.

### Request Body

| Field           | Type                      | Required | Description                                            |
|-----------------|---------------------------|----------|--------------------------------------------------------|
| `session_id`    | `string`                  | Yes      | Session this feedback refers to.                       |
| `message_id`    | `string`                  | No       | Specific message within the session.                   |
| `reward`        | `number`                  | Yes      | Scalar reward (must be within configured `reward_range`). |
| `confidence`    | `number`                  | No       | Confidence weight (0–1).                               |
| `dimensions`    | `Record<string, number>`  | No       | Multi-dimensional reward breakdown.                    |
| `feedback_text` | `string`                  | No       | Free-form human commentary.                            |

### Response `201 Created`

```json
{
  "id": "fb-20250115-001",
  "session_id": "sess-abc123",
  "reward": 2,
  "confidence": 0.9,
  "created_at": "2025-01-15T11:00:00Z"
}
```

### Example

```bash
curl -X POST http://localhost:8001/v1/learning/feedback \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "sess-abc123",
    "reward": 2,
    "confidence": 0.9,
    "feedback_text": "Accurate and well-structured response."
```

## Error Responses

All endpoints return standard HTTP error codes with a JSON body:

```json
{
  "error": {
    "message": "Description of the error",
    "type": "invalid_request_error",
    "code": "document_not_found"
  }
}
```

| Status | Meaning                                                  |
|--------|----------------------------------------------------------|
| `400`  | Malformed request, invalid reward range, missing fields. |
| `404`  | Referenced session or job not found.                     |
| `409`  | Training job conflict (GPU busy, duplicate submission).  |
| `422`  | Reward outside configured `reward_range`.                |
| `500`  | Internal error (Axolotl failure, R2 read/write failure). |
| `503`  | Training subsystem unavailable (GPU offline).            |
